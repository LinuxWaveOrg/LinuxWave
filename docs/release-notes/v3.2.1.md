# LinuxWave 3.2.1 Release Notes

- Released: 2026-11-08, build `312A1137`
- Branch: `3.2` (the `v3.2.0` tag stays at `298a64f`)
- Previous release: [v3.2.0](v3.2.0.md)

> **Security update.** Two paths that used to take over — or delete — a directory MacWave
> did not create are closed. The command line, the data formats and the install layout are
> unchanged.

## Why upgrade

### 1. Installing into a system directory took over that directory

`install.sh` used to accept any custom directory that was not `..`, not control characters,
not non-ASCII, not relative, not `//` and not `/`. What ran afterwards:

```bash
sudo chown -R root:root "$BASE_DIR"          # non-shared system install (3.2.1 on)
sudo chown -R "$CURRENT_USER": "$BASE_DIR"   # the old behaviour
rm -rf "$BASE_DIR"                           # rollback when the licence is declined
```

If `BASE_DIR` is `/usr/local` — where other software lives — those two do **take the whole
directory over** and **delete it**. Measured on the old validation, every one of these paths
was accepted:

```
/usr/local   /opt   /etc   /usr   /bin   $HOME
```

**As of 3.2.1**: those system directories themselves are always refused (compared for exact
equality, so subdirectories such as `/opt/linuxwave` are unaffected), and so is a directory
that already exists, is not empty, and was not created by LinuxWave.

### 2. Install and uninstall deleted directories taken from a config file

`uninstall.sh` reads `base_dir` from `config.json` and, whenever it was not under `$HOME`,
handed it straight to `sudo rm -rf`. A user-level config is writable by any process running
as that user — one edited `base_dir` was enough to delete `/usr/local` or a home directory.

**As of 3.2.1**: only a directory that really is a LinuxWave install (it must contain
`lib/wave.py`) is removed; system directories, `$HOME` and anything else are skipped, each
with its own reason:

```
🌊 Skipping /usr/local: a system directory.
🌊 Skipping /home/you: your home directory.
🌊 Skipping /opt/other-tool: not a LinuxWave install (no lib/wave.py).
🌊 Nothing was deleted there. If you are sure, remove it yourself.
```

## Also tightened: a system-wide tree is owned by root

A **non-shared** system install (`/opt/linuxwave`, `/usr/local/linuxwave` and any custom
directory outside your home) used to hand the tree to whoever installed it, so
`links/<name>` was writable by that account — while sitting on the system `PATH`, where
other users, scripts and root may run it. That is a local privilege-escalation path.

Those trees are now `root:root` with mode 755: everyone can read and execute, changing them
needs `sudo`. The cost is stated plainly — `sudo` searches its own `PATH`, so give the full
path:

```
sudo /opt/linuxwave/lib/wave install <package>
```

If you want `wave install` without `sudo`, use the shared install (option 4). That path is
untouched by this release and still writes through the `linuxwave` group. The runtime checks
writability **before downloading** and prints a command you can copy.

## Regression

New `scripts/dir_guard_test.sh`, 62 assertions, fully offline, seconds:

| Coverage | Content |
| --- | --- |
| Verdicts | 25 system directories, `$HOME`, non-LinuxWave directories → refused; `/opt/linuxwave`, `/usr/local/linuxwave`, `~/.local/linuxwave` → allowed |
| False-positive guard | a tree that already has `lib/wave.py` can still be reinstalled / upgraded |
| Old checks | empty, `..`, relative, `/`, `//` are still refused |
| Ownership | non-shared system install becomes `root:root` 755, after the launcher write; the shared install is unaffected |
| Uninstall | the uninstaller is run for real against a stub `sudo`: a non-LinuxWave directory and `$HOME` survive, a real install tree is removed as before |

## Compatibility

- **No command-line change**: no flag was added, removed or altered.
- **No data-format change**: neither the index nor the configuration changes.
- **No install-layout change**: still `lib/`, `pkg/`, `surfboard/`.
- **Two behaviour changes**: a system directory can no longer be an install root; a
  non-shared system install is now `root:root` 755, so changing packages afterwards needs
  `sudo` (the shared install is unaffected).

## Upgrading

```bash
wave selfupdate
```

(`selfupdate` rewrites the root-owned `/etc/linuxwave_config`, so expect one `sudo` prompt.)

An existing shared install is unchanged. An existing **non-shared** system install keeps its
current owner after upgrading — **re-run `install.sh` once** to switch it to `root:root`.

# 安全更新

**LinuxWave 3.2.1** · Build number: **312A1137** · 发布于 **2026-11-08** · 发布分支：`3.2`

> 建议所有用户升级。这一版堵掉两个「安装/卸载时按路径递归改权限、删目录」的漏洞，
> 与 MacWave 4.3.0 / 4.3.1 修的是同一类问题。命令、数据格式、安装布局都不变。

## 为什么要升级

### ① 装到系统目录时，会把那个目录整个接管过来

`install.sh` 的目录校验以前只挡了 `..`、控制字符、非 ASCII、相对路径、`//` 和 `/`。
之后的动作是：

```bash
sudo chown -R root:root "$BASE_DIR"          # 非共享的系统级安装（3.2.1 起）
sudo chown -R "$CURRENT_USER": "$BASE_DIR"   # 3.2.1 之前的写法
rm -rf "$BASE_DIR"                           # 拒绝协议时的回滚
```

如果 `BASE_DIR` 是 `/usr/local` 这种「别的软件的家」，这两件事分别是**把整个目录接管过来**
和**删掉它**。实测旧版的校验对下面这些路径全部放行：

```
/usr/local   /opt   /etc   /usr   /bin   $HOME
```

**3.2.1 起**：这些系统目录本身一律拒绝（按完全相等判，`/opt/linuxwave` 这类子目录不受影响）；
已存在且非空、又不是 LinuxWave 安装的目录也拒绝。

### ② 安装/卸载会顺着配置里的路径删目录

`uninstall.sh` 从 `config.json` 读 `base_dir`，只要不在 `$HOME` 下就直接 `sudo rm -rf`。
用户级配置对任何以该用户身份运行的进程都可写 —— 一条被改过的 `base_dir` 就能删掉
`/usr/local` 或家目录。

**3.2.1 起**：只删确实含 `lib/wave.py` 的 LinuxWave 安装树；系统目录、`$HOME`、
非 LinuxWave 目录一律跳过，并逐条说明理由：

```
🌊 Skipping /usr/local: a system directory.
🌊 Skipping /home/you: your home directory.
🌊 Skipping /opt/other-tool: not a LinuxWave install (no lib/wave.py).
🌊 Nothing was deleted there. If you are sure, remove it yourself.
```

## 顺带收紧：系统级安装树归 root

`/opt/linuxwave`、`/usr/local/linuxwave` 这类**非共享**的系统级安装，树以前归安装者所有，
`links/<名>` 对该用户可写，而它在系统 `PATH` 上会被别的用户、脚本甚至 root 执行 —— 本地提权。
现在这些安装树变成 `root:root`、权限 755：所有人可读可执行，改动需要 `sudo`。

代价说清楚：装包/升级/卸载要写全路径，因为 `sudo` 用的是它自己的 `PATH`：

```
sudo /opt/linuxwave/lib/wave install <包名>
```

想要「不带 `sudo` 的 `wave install`」，用共享安装（选项 4）—— 那条路不受本版影响，
仍然由 `linuxwave` 组共享写。运行时会在**下载之前**检查可写性，并给出可照抄的命令。

## 回归

新增 `scripts/dir_guard_test.sh`，62 条断言，纯离线、秒级：

| 覆盖 | 内容 |
| --- | --- |
| 判定 | 25 个系统目录、`$HOME`、非 LinuxWave 目录 → 拒绝；`/opt/linuxwave`、`/usr/local/linuxwave`、`~/.local/linuxwave` → 放行 |
| 防误杀 | 已有 `lib/wave.py` 的安装树仍可重装/升级 |
| 旧校验 | 空、`..`、相对路径、`/`、`//` 仍然拒绝 |
| 属主 | 非共享系统级安装归 `root:root`、755 语义；交还在写 launcher 之后；共享安装仍归 `linuxwave` |
| 卸载 | 用一个假的 `sudo` 真跑卸载脚本：非 LinuxWave 目录、`$HOME` 保留，真正的安装树照常删除 |

## 兼容性

- **不涉及命令行变更**：没有新增、删除或改变任何旗标。
- **不涉及数据格式变更**：索引、配置都不变。
- **安装布局不变**：还是 `lib/`、`pkg/`、`surfboard/`。
- **行为变化两处**：系统目录不再能当安装根；非共享的系统级安装改成 `root:root` 755，
  之后改动软件包需要 `sudo`（共享安装不受影响）。

## 升级方式

```bash
wave selfupdate
```

（`selfupdate` 会重写 root 属主的 `/etc/linuxwave_config`，因此会提示一次 `sudo`。）

已有的共享安装照旧；已有的非共享系统级安装升级后仍是原属主，**重新跑一次 `install.sh`**
才会转成 `root:root`。
