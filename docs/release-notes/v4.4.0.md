# LinuxWave 4.4.0

**LinuxWave 4.4.0** · Build number: **324E1821** · Released **2026-11-20** · Release branch: `4.4`

This release does two things. It lines the version number up with MacWave 4.4 — the code line
these files are ported from — and it switches on signature verification, which was present as
code but not as a working trust chain in 4.0.0.

## Upgrading

`wave selfupdate` is enough. Both `4.0` and `4.4` have major version `4`, so this is not a
cross-major update and the installer is not needed:

```bash
wave selfupdate
```

If you are still on 3.x, use the installer instead — that one *is* cross-major.

## 1. Signature verification is actually on

4.0.0 shipped the verifier and the key pins but not the keys themselves:

| Piece | In 4.0.0 | In 4.4.0 |
| --- | --- | --- |
| RSA public key embedded in `lib/install.sh` | empty string → the whole check returned early | real key, embedded by `scripts/embed_rsa_pub.py` |
| `Keys/linuxwave-rsa.pub.pem` | absent | present |
| `Keys/D0E229FB.asc` (GPG) | absent → `net/signature.py` always answered `no-keys` | present, matching `PINNED_FINGERPRINTS` |
| `linuxwavedata/latest.toml.sig` | absent | present |

Two independent layers, both optional to fail hard:

1. **The self-update probe.** `linuxwavedata/latest.toml` comes with a detached RSA/SHA-256
   signature. The public key used to check it is embedded in `lib/install.sh`, not read from
   the install tree — anything that can replace the data can also replace a key sitting next
   to it, so verifying against that would prove nothing.
2. **Release assets.** `SHA256SUMS` covers every file this release attaches, and
   `SHA256SUMS.asc` is a GPG signature over it. The public key ships in `Keys/D0E229FB.asc`
   and the fingerprint is pinned in `net/signature.py`.

A mismatch is a **warning, not a failure**, for now — `LINUXWAVE_STRICT_HASHES=1` turns it
into a hard failure:

```bash
# check the data by hand
gpg --verify SHA256SUMS.asc SHA256SUMS          # Good signature
shasum -a 256 -c SHA256SUMS                     # every file OK

# run the installer in strict mode
LINUXWAVE_STRICT_HASHES=1 /bin/bash -c "$(curl -fsSL https://github.com/LinuxWaveOrg/LinuxWave/releases/latest/download/install.sh)"
```

The RSA key pair is shared with MacWave (same publisher, two products); the private key never
enters a repository. See `Keys/description.md`.

## 2. What else changed since 4.0.0

- **`wave upgrade --all`** — upgrade every installed package in one command.
- **`wave info` output formats** — `--json`, `--yaml`, `--toml`, `--raw`.
- **Man pages and info files** — 34 files (`man/man1/wave*.1`, `info/wave*.info`), and
  `wave shellenv` now sets `MANPATH` so `man wave` works out of the box.
- **`install.sh --dry-run` walks the whole flow**, and `--raw` gives it a hash-mark progress
  bar instead of a redrawn one.
- **Fixes**, all of which were visible to users:
  - `latest` no longer summarises "everything is up to date" when the index could not be read.
  - Diagnostics print the address that failed, and rule out the missing `ref` segment first.
  - The build number now takes part in version comparison (`wave selfupdate` used to miss a
    rebuild of the same version).
  - Download file names go through a whitelist.
  - `--skip-ssl` and `LINUXWAVE_CACERT` now really cover every request point.
  - Installation privilege is decided by **write access**, not by the directory name.
  - `uninstall` no longer hits a `NameError` on the silent-output import.
- **Refactor:** dependency-reference parsing moved into `surfboard/querier.py`;
  `surfboard/depsversionparser.py` is gone and the update commands delete the stale copy on
  upgrade.

## 3. Known limitations

- **No `min_os` equivalent.** MacWave 4.3 added a `min_os` floor read from each package's
  Mach-O `minos`. Linux has no such field, and LinuxWave does not substitute a glibc version
  requirement — a package that needs a newer glibc will fail at run time, not at install time.
- **bash 4.4 or newer** is required for the installer and the self-update script.
- Signature verification is enforced only with `LINUXWAVE_STRICT_HASHES=1`.

## 4. Assets

`99` assets = `95` source files (every `.py` / `.sh` in this tag, flattened) + `2` source-tree
archives + `SHA256SUMS` + `SHA256SUMS.asc`.

| Asset | What it is |
| --- | --- |
| `*.py`, `*.sh` | every source file at this tag, without directories |
| `linuxwave-4.4.0-archive.tar`, `.tar.gz` | the whole tree, top-level directory `linuxwave-4.4.0/` |
| `SHA256SUMS` | SHA-256 of every asset above |
| `SHA256SUMS.asc` | detached GPG signature over `SHA256SUMS` |

# LinuxWave 4.4.0

**LinuxWave 4.4.0** · 构建号：**324E1821** · 发布于 **2026-11-20** · 发布分支：`4.4`

这一版做两件事：把版本号与 MacWave 4.4 对齐（这些文件就是从那条线移植过来的），
以及把**验签真正接上** —— 4.0.0 里有代码、有指纹，但没有钥匙。

## 升级方式

`wave selfupdate` 就够。`4.0` 与 `4.4` 的主版本号都是 `4`，不算跨大版本，不需要重装：

```bash
wave selfupdate
```

还在 3.x 的要用安装器 —— 那才是跨大版本。

## 1. 验签真正接通了

4.0.0 发了验证器和指纹白名单，却没发钥匙：

| 部件 | 4.0.0 | 4.4.0 |
| --- | --- | --- |
| `lib/install.sh` 内嵌的 RSA 公钥 | 空串 → 整段验签提前返回 | 真公钥，由 `scripts/embed_rsa_pub.py` 内嵌 |
| `Keys/linuxwave-rsa.pub.pem` | 缺 | 有 |
| `Keys/D0E229FB.asc`（GPG） | 缺 → `net/signature.py` 永远回 `no-keys` | 有，与 `PINNED_FINGERPRINTS` 一致 |
| `linuxwavedata/latest.toml.sig` | 缺 | 有 |

两层彼此独立，都可以被抬成硬失败：

1. **自更新探针。** `linuxwavedata/latest.toml` 带一份 RSA/SHA-256 分离签名。验签用的
   公钥**内嵌在 `lib/install.sh` 里**，不读安装树 —— 能替换数据的人也能替换放在它旁边的
   公钥，拿那份验等于自证。
2. **发布产物。** `SHA256SUMS` 覆盖这一版附上的每个文件，`SHA256SUMS.asc` 是对它的 GPG
   签名。公钥随 `Keys/D0E229FB.asc` 一起装进安装树，指纹钉在 `net/signature.py` 里。

目前不符是**警告，不是失败**；`LINUXWAVE_STRICT_HASHES=1` 才会硬失败：

```bash
# 手工核一遍数据
gpg --verify SHA256SUMS.asc SHA256SUMS          # Good signature
shasum -a 256 -c SHA256SUMS                     # 每个文件 OK

# 以严格模式跑安装器
LINUXWAVE_STRICT_HASHES=1 /bin/bash -c "$(curl -fsSL https://github.com/LinuxWaveOrg/LinuxWave/releases/latest/download/install.sh)"
```

RSA 那把钥与 MacWave 共用（同一个维护者在发这两个产品），私钥从不进仓库。
细节见 `Keys/description.md`。

## 2. 自 4.0.0 以来的其它改动

- **`wave upgrade --all`** —— 一条命令升级所有已装的包。
- **`wave info` 支持格式** —— `--json`、`--yaml`、`--toml`、`--raw`。
- **man 页与 info 文件** —— 共 34 个（`man/man1/wave*.1`、`info/wave*.info`），
  `wave shellenv` 顺带设 `MANPATH`，装完就能 `man wave`。
- **`install.sh --dry-run` 走完全程**，`--raw` 下进度用井号刻度而不是光标重绘。
- **修复**（都是用户看得见的问题）：
  - `latest` 在索引读不到时不再汇总成「全是最新」。
  - 诊断信息印出失败的地址，并先排掉「少了 ref 段」这种可能。
  - 构建号参与版本比较（此前同一版本重新构建时 `wave selfupdate` 会漏掉）。
  - 下载文件名过一遍白名单。
  - `--skip-ssl` 与 `LINUXWAVE_CACERT` 现在真的覆盖每个请求点。
  - 安装是否要提权按**写权限**判定，不再看目录名。
  - `uninstall` 补上漏掉的 silent 导入（此前是 `NameError`）。
- **重构**：依赖引用解析并进 `surfboard/querier.py`，`surfboard/depsversionparser.py`
  删除；升级时更新脚本会清掉旧的那份。

## 3. 已知限制

- **没有 `min_os` 的等价物。** MacWave 4.3 增加了从每个包 Mach-O 的 `minos` 读出的
  下限。Linux 没有这个字段，LinuxWave 也没有用 glibc 版本要求去替代 —— 需要更新
  glibc 的包会在**运行时**失败，而不是安装时被挡下。
- 安装器与自更新脚本要求 **bash 4.4 或更高**。
- 验签只在 `LINUXWAVE_STRICT_HASHES=1` 时硬失败。
