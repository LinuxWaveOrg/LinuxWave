# 重要更新

**LinuxWave 3.2.0** · Build number: **302D1838** · 发布于 **2026-10-29** · 发布分支：`3.2`

> 建议所有用户升级。这一版补齐了三个长期缺口：`wave upgrade`、`--max-time`，以及**镜像真正生效**。

## 为什么要升级

**① 装到最新版这件事，以前只能自己拼。** `wave install jq@1.8.2` 要求你**先知道** 1.8.2 是最新版；
版本是共存的（`bin/<名字>@<版本>` 各占一个目录），所以「升级」本质上就是再装一个，旧的那份不会自己消失。
现在 `wave upgrade jq` 直接对着索引装最新版，`-X` 才会把更旧的版本清掉。

**② 所有请求的超时以前都写死 30 秒。** 烂链路上只能干等，也没法为一次大批量安装放宽。

**③ 镜像地址以前配了也不起作用。** 七种对外地址 3.1.0 就已经可以覆盖，但 `BOTTLE` / `DEPS`
这两个只是「声明」，安装路径仍然照索引里的 `url` 去上游取。这一版把它接上了。

## 这一版做了什么

**`wave upgrade <包名> [flags]`。** 版本由索引决定，不接受 `包名@版本`
（要装指定版本请用 `wave install <包名>@<版本>`，报错信息里也会这么说）。

```
wave upgrade jq           # 装到最新版，旧版本留着
wave upgrade jq -X        # 装到最新版，并清掉更旧的
```

「同时移除旧版本」有**四种完全等价**的写法：`-X`、`--remove-old-versions`、
`--remove-old-version`、`--rov`，短旗标簇也认（`-Xv` 等于 `-X -v`）。
**帮助里只宣传 `-X, --remove-old-versions`** —— 但另外两个长写法必须继续能用：
3.2.0 发布过单数形式，已经写进别人的脚本和 CI 里了。文档收敛不是行为收缩。

几个边界：

- 索引比本机旧时（版本被撤下）只警告、**不降级**；
- 已经是最新时不下载任何字节，但会把不带版本号的链接重新指到最新版 ——
  否则「已经是最新」却仍让 `wave` 命令跑着旧版本；
- 清理旧版本：只有一个就直接删；多个先问一次 Y/n；**非交互环境不删**（保留比误删安全），
  答 n 才进入逐项选择。

**`--max-time`。** 接受 `40` / `40s` / `1min` / `1min20s` / `2h` / `1d`，纯数字按秒。
`install` / `upgrade` / `selfupdate` 都认，并且对**该条命令的所有请求**生效
（取索引、取 `@common`、取版本记录、下载产物、以及自更新脚本里的每一次 curl）。

写错不会静默兜底：`--max-time=10minn` 直接报错并给出可用写法。悄悄按 30 秒跑比失败更难查。

**镜像真正生效（B 档）。** 配了 `LINUXWAVE_BOTTLE_DOMAIN` / `LINUXWAVE_DEPS_DOMAIN` 就走我们自己的存储，
文件名按 `<包名>@<版本>.<架构><扩展名>`（裸二进制没有扩展名）。三条规则：

| 情形 | 行为 |
| --- | --- |
| 配了镜像 | 从镜像取，文件名按 payload 命名 |
| 没配镜像（域名为空） | 回落到索引的 `url`，**3.1.x 的行为完全不变** |
| `--install-from-source` | 一律回上游，**即使配了镜像** |

镜像 URL 里的 `@` 会被编码成 `%40`，静态服务器解码即得原名；扩展名由索引的 `file` 字段带进来，
绝不会把 `.tar.bz2` 截成 `.bz2`。走镜像但数据缺 `file` 时**硬失败**，不去猜格式。

## 已知限制

- **镜像需要自己配**：不配 `LINUXWAVE_BOTTLE_DOMAIN` / `LINUXWAVE_DEPS_DOMAIN` 时行为与 3.1.0 完全一致；
- **真机从镜像取字节这条路径还没有跑过**：开发机对外网络不稳定，只做了 `file://` / 本地假根的离线验证；
- `upgrade -X` 在多版本时依赖交互确认，无人值守场景请只用「只有一个旧版本」的情形，或先手工 `wave uninstall`；
- 4.0 的自更新数据布局（`linuxwavedata/latest.toml` + `<版本>/update_commands.sh`）**仍未接线**，
  自更新仍走 `versiondata/latest_version` + `update_command`。

# Major update

**LinuxWave 3.2.0** · Build number: **302D1838** · Release branch: `3.2`

> Upgrading is recommended. This release fills three long-standing gaps: `wave upgrade`,
> `--max-time`, and a mirror that actually takes effect.

### Why upgrade

**Upgrading used to be manual.** `wave install jq@1.8.2` requires you to already know that 1.8.2
is the latest. Versions coexist (each lives in its own `bin/<name>@<version>` directory), so
"upgrading" is really just installing another one — the old copy never goes away by itself.
`wave upgrade jq` now targets the latest version in the index, and only `-X` removes the older ones.

**Every request used to have a hard-coded 30 second timeout**, which is painful on a bad link and
impossible to relax for a large batch install.

**Mirror addresses did not take effect.** All seven remote addresses could be overridden since
3.1.0, but `BOTTLE` and `DEPS` were declaration only — the installer still followed the index's
`url` to the upstream. This release connects them.

### What this release does

**`wave upgrade <package> [flags]`** decides the version from the index and rejects
`package@version` (use `wave install package@version` for an exact version; the error says so).

"Also remove old versions" has **four equivalent spellings**: `-X`, `--remove-old-versions`,
`--remove-old-version`, `--rov`, and short flag clusters work too (`-Xv` equals `-X -v`).
**Help advertises only `-X, --remove-old-versions`**, but the other two long forms must keep
working: the singular one shipped in 3.2.0 and is already in other people's scripts.

Boundaries: an index older than the machine only warns (never downgrades); when already latest
nothing is downloaded but the unversioned link is re-pointed; removing old versions asks once
when there are several and does nothing without a terminal (keeping is safer than deleting).

**`--max-time`** accepts `40` / `40s` / `1min` / `1min20s` / `2h` / `1d`, bare numbers are seconds.
Honoured by `install` / `upgrade` / `selfupdate` for every request of that command. A malformed
value is an error, not a silent fallback to 30 seconds.

**The mirror takes effect (tier B).** With `LINUXWAVE_BOTTLE_DOMAIN` / `LINUXWAVE_DEPS_DOMAIN`
set, payloads come from our own store, named `<name>@<version>.<arch><ext>`.
No mirror configured keeps 3.1.x behaviour exactly; `--install-from-source` always goes upstream.
A `@` in the URL is percent-encoded to `%40`; the extension comes from the index's `file` field,
so `.tar.bz2` is never truncated to `.bz2`. Missing `file` while using a mirror is a hard error.

### Measurements

Sandbox regression (`unshare -rm` plus an offline `file://` mirror, a real install to real paths):
`sandbox_test.sh` 163/0/0; `upgrade_test.sh` 19 checks; `timeout_test.sh` 35; `payload_test.sh` 16;
`help_test.sh` 5; domains / mirror / link / checksum all pass (checksum has two network SKIPs).

CI: `Portable Python` runs a real `install.sh` end to end, then verifies the entry point still
prints the version with `PATH=/nonexistent`. `Format Test` runs the full suite on 3.14 and 3.15.

### Known limitations

- A mirror has to be configured; without `LINUXWAVE_BOTTLE_DOMAIN` / `LINUXWAVE_DEPS_DOMAIN`
  the behaviour is identical to 3.1.0.
- Fetching bytes from a real mirror has not been exercised on a real machine yet; only offline
  `file://` / fake-root verification was done.
- `upgrade -X` asks for confirmation when several versions exist; for unattended use, only rely
  on the single-old-version case or uninstall manually first.
- The 4.0 self-update layout (`linuxwavedata/latest.toml` + `<version>/update_commands.sh`) is
  still not wired; self-update continues to use `versiondata/latest_version` + `update_command`.
