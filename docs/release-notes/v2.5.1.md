# Release Note 更新日志

## 新增：共享安装（菜单选项 4）

安装菜单新增一个官方选项 **`/home/linuxwave/.linuxwave`**，效果等价于 **Linuxbrew 的 `/home/linuxbrew`**：一台机器上装一次，**所有用户**都能使用 `wave`。

选它之后，安装器会自动完成过去需要手工做的全部事情：

- 若 `linuxwave` 账号不存在则**自动创建**（`useradd -m -d /home/linuxwave`）
- 安装到 `/home/linuxwave/.linuxwave`，安装树归 `linuxwave` 所有
- 配置固定写入 **`/etc/linuxwave_config`**（见下）
- 放宽权限：家目录改 `755`、安装树 `a+rX`，让其他用户可读可执行
- 同时把 `PATH` 写入 `linuxwave` 与调用者各自的 shell 配置

> **注意：选项编号有变化。** 自定义目录从 **4 移到了 5**。照着旧文档操作时会选错，旧版安装器请仍按旧编号。

## New: Shared Install (Menu Option 4)

The menu now offers **`/home/linuxwave/.linuxwave`**, mirroring **Linuxbrew's `/home/linuxbrew`**: install once per machine and **every user** can run `wave`.

Picking it makes the installer do everything that previously had to be done by hand:

- creates the `linuxwave` account if missing (`useradd -m -d /home/linuxwave`)
- installs to `/home/linuxwave/.linuxwave`, owned by `linuxwave`
- writes the config to **`/etc/linuxwave_config`** (see below)
- opens permissions: home to `755`, the install tree to `a+rX`, so other users can read and execute
- adds `PATH` to both `linuxwave`'s shell config and the invoking user's

> **Note: the option numbers changed.** Custom moved from **4 to 5**. Following older instructions will pick the wrong entry; on an older installer, use the old numbering.

## 为什么需要它

LinuxWave 原有的官方目录各有取舍：

- `~/.local/linuxwave` —— 无需 sudo，但**只有装它的那个用户**能用（家目录默认 750，别人连进入都不行）
- `/opt/linuxwave`、`/usr/local/linuxwave` —— 全机可用，但**每次装包都要 sudo**，且包管理器以 root 身份往 root 属主的目录里写文件

共享安装补上了中间那一档：**全机可用，且后续装包无需提权**。

## Why It Is Needed

The previous official directories each forced a trade-off:

- `~/.local/linuxwave` - no sudo, but **only the user who installed it** can use it (a home directory defaults to 750, so nobody else can even enter it)
- `/opt/linuxwave`, `/usr/local/linuxwave` - usable machine-wide, but **every install needs sudo**, and the package manager writes into a root-owned tree as root

The shared install fills the gap: **usable machine-wide, with no privilege escalation for later installs**.

## 好处

- **一次安装，全机可用**：所有用户都能运行 `wave` 与已安装的软件包
- **装包不再需要 sudo**：以 `linuxwave` 身份操作即可（权限问题只出现在安装那一次）
- **与发行版目录彻底隔离**：不碰 `/usr/local/bin`、`/opt`，不与 `apt`/`dnf` 装的同名程序抢路径
- **卸载干净**：删掉目录与配置即可，不留残渣
- **属主明确**：安装树归一个专用账号，而不是 root、也不是某个真人的家目录，便于共享与审计
- **可整体搬迁**：每个 ELF 的 `RUNPATH` 都是 `$ORIGIN` 相对路径，整个目录搬走仍然可用

## Benefits

- **Install once, use everywhere**: every user can run `wave` and the packages it installed
- **No sudo for package installs**: operate as `linuxwave`; the privilege prompt happens only during installation
- **Fully isolated from distributions**: nothing touches `/usr/local/bin` or `/opt`, and it never competes with same-named `apt`/`dnf` programs
- **Clean removal**: delete the directory and the config, and nothing is left behind
- **Unambiguous ownership**: the tree belongs to a dedicated account, not root and not a real person's home directory
- **Relocatable**: every ELF's `RUNPATH` is `$ORIGIN`-relative, so moving the whole directory keeps it working

## 前置准备

选择这个路径之前，请确认：

1. **sudo 可用** —— 仅安装时需要，用于创建 `/home/linuxwave` 与写入 `/etc/linuxwave_config`
2. **patchelf 已安装** —— **必需**，缺了它依赖库无法重定位，`wget`、`tmux`、`htop`、`ncdu` 等带依赖的包会跑不起来

   ```
   sudo apt install patchelf        # Debian / Ubuntu
   sudo dnf install patchelf        # Fedora / RHEL
   sudo pacman -S patchelf          # Arch
   ```

3. **Python 3.14 及以上** —— LinuxWave 与 `.conda` 软件包都需要

安装器在选定该选项后会把这份清单再打印一次。

## Prerequisites

Before choosing this path, make sure:

1. **sudo is available** - needed only during installation, to create `/home/linuxwave` and write `/etc/linuxwave_config`
2. **patchelf is installed** - **required**; without it dependency libraries cannot be relocated and packages with dependencies (`wget`, `tmux`, `htop`, `ncdu`, ...) will fail to run

   ```
   sudo apt install patchelf        # Debian / Ubuntu
   sudo dnf install patchelf        # Fedora / RHEL
   sudo pacman -S patchelf          # Arch
   ```

3. **Python 3.14 or above** - required by LinuxWave and by `.conda` packages

The installer prints this list again once the option is chosen.

## 配置文件为何固定放 /etc

共享安装**恒定**使用 `/etc/linuxwave_config`，与运行者是谁、其 `$HOME` 是什么都无关。

原因是用户级配置会按**每个调用者各自的 `$HOME`** 解析。若配置写进 `linuxwave` 自己的 `~/.config`，其他用户运行 `wave` 时会去找他们自己的家目录，那里什么都没有，只会得到：

```
🌊 Error: Configuration file not found or invalid.
```

这句提示是误导的 —— 他们并没有装过。把配置放在系统级位置，才能让全机用户解析到**同一个**安装。

## Why the Config Always Goes to /etc

A shared install **always** uses `/etc/linuxwave_config`, regardless of who runs it or what their `$HOME` is.

The reason is that a user-level config resolves against **each caller's own `$HOME`**. If the config were written into `linuxwave`'s own `~/.config`, other users running `wave` would look inside their own home and find nothing but:

```
🌊 Error: Configuration file not found or invalid.
```

That message is misleading - they never installed anything. Only a system-level location lets every user resolve the **same** install.

## 变更：`/usr/local` 不再限于 x86_64

MacWave 的目录菜单把 `/usr/local/linuxwave` 标注为 **"Only Intel Mac"**，只对 Intel 机器提供。那是 **macOS 侧的顾虑**：Apple 芯片上不建议写入 `/usr/local`，更推荐 `/opt` 之下的前缀，而且 `/usr/local` 里往往还残留着 Intel 时代的文件，混在一起容易出问题。

**Linux 没有这层顾虑。** `/usr/local` 正是 FHS 为"本地自行安装的软件"规定的位置，x86_64 与 arm64 一视同仁，`apt` / `dnf` 也不会去动它。

因此 LinuxWave **去掉了这个限制**：`/usr/local/linuxwave` 现在**两种架构都提供**。

副作用是 **两个架构的目录菜单从此完全相同**，原先按架构分叉的那段代码已合并，菜单统一为：

```
1. ~/.local/linuxwave
2. /opt/linuxwave
3. /usr/local/linuxwave
4. /home/linuxwave/.linuxwave (shared, all users)
5. other (enter custom directory)
```

`uninstall.sh` 的候选路径列表也同步去掉了架构判断。

## Change: /usr/local Is No Longer x86_64 Only

MacWave's menu labelled `/usr/local/linuxwave` as **"Only Intel Mac"** and offered it on Intel machines alone. That was a **macOS-side concern**: on Apple silicon `/usr/local` is not the recommended place to write, a prefix under `/opt` is preferred, and `/usr/local` often still holds Intel-era leftovers that mix badly with new files.

**Linux has no such concern.** `/usr/local` is exactly where FHS puts software you install yourself, it is identical for x86_64 and arm64, and `apt` / `dnf` never touch it.

LinuxWave therefore **drops the restriction**: `/usr/local/linuxwave` is now offered on **both architectures**.

As a consequence **the menu is now identical on every architecture**, the previously forked code is merged, and the menu reads:

```
1. ~/.local/linuxwave
2. /opt/linuxwave
3. /usr/local/linuxwave
4. /home/linuxwave/.linuxwave (shared, all users)
5. other (enter custom directory)
```

`uninstall.sh`'s candidate list drops the architecture check as well.

## 卸载

`uninstall.sh` 已同步支持共享安装：会删除安装树与 `/etc/linuxwave_config`，并清理 `linuxwave` 与调用者两边的 `PATH`。

随后它会**询问**是否一并删除 `linuxwave` 账号。**请留意警告**：`userdel -r` 会连同家目录 `/home/linuxwave` 一起删除，那里面的其他内容也会消失。该账号是 LinuxWave 专用的，通常可以安全删除；选择保留时会打印手工删除命令。

## Uninstall

`uninstall.sh` now understands the shared install: it removes the install tree and `/etc/linuxwave_config`, and cleans `PATH` from both `linuxwave`'s and the invoking user's shell config.

It then **asks** whether to remove the `linuxwave` account. **Read the warning**: `userdel -r` also deletes the home directory `/home/linuxwave`, so anything else stored there goes with it. The account is dedicated to LinuxWave and is normally safe to remove; declining prints the manual command instead.

## 提示

- **只有 `linuxwave` 与 root 能安装软件包。** 其他用户可运行 `wave` 与已装好的软件，但 `wave install` 会因权限失败。若需多人安装，见 `.templates/SPECIAL/INSTALL_BY_INTERNET.md` 里的用户组与 setgid 做法。
- 为共享而放宽的家目录权限意味着 `/home/linuxwave` 下**任何**文件都变为其他用户可读，请勿在其中存放私密文件。
- 安装目录若被 `/home` 的备份或配额覆盖，或 `/home` 以 `noexec` 挂载，则不适合该路径。

## Tips

- **Only `linuxwave` and root can install packages.** Other users can run `wave` and the packages already installed, but `wave install` fails on permissions. For multi-user installs, see the group and setgid setup in `.templates/SPECIAL/INSTALL_BY_INTERNET.md`.
- Opening the home directory for sharing means **every** file under `/home/linuxwave` becomes readable by other users; do not keep private files there.
- This path is a poor fit when `/home` is covered by backups or quotas, or when `/home` is mounted `noexec`.
