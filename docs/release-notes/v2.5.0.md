# Release Note 更新日志

## LinuxWave 的首个版本

这是 **LinuxWave 的首个正式版本**。

LinuxWave 是 MacWave 的**官方 Linux 移植版**。从 MacWave 2.0 起，MacWave 主线**不再支持 Linux**；如果你在 Linux 上使用 MacWave 并希望继续获得更新，请改用 LinuxWave。

它与 MacWave 是**同一套包管理器**——命令、目录布局、依赖管理、无版本号软链接的行为都一致，区别只在**目标平台**：LinuxWave 分发与安装 **Linux（ELF）**软件包。

版本号从 **2.5** 起算，而不是 1.0：LinuxWave 承接的是 MacWave 2.5 这条线，版本号与它分叉时的上游保持一致，便于对照。

## First Release of LinuxWave

This is the **first official release of LinuxWave**.

LinuxWave is the **official Linux port of MacWave**. Starting with MacWave 2.0, the main MacWave project **no longer supports Linux**; if you have been using MacWave on Linux and want to keep receiving updates, move to LinuxWave.

It is the **same package manager** - commands, directory layout, dependency handling and versionless-link behavior are identical. Only the **target platform** differs: LinuxWave ships and installs **Linux (ELF)** packages.

The version starts at **2.5** rather than 1.0: LinuxWave carries the MacWave 2.5 line forward, so the number matches the upstream point it forked from.

## 与 MacWave 的差异

### 目标平台与依赖重定位

- MacWave 处理 **Mach-O**，用 **Xcode Command Line Tools**（`otool`、`install_name_tool`）；LinuxWave 处理 **ELF**，用 **`patchelf`**
- 每个 ELF 的 `RUNPATH` 被改写成 **`$ORIGIN` 相对路径**，指向产物自己的 `lib/`、`lib64/`，再指向它依赖的那些已安装依赖的目录；全部相对，**整个安装目录搬走也依然有效**
- **不存在代码签名步骤**：ELF 不强制签名，路径改完即可运行。MacWave 侧与签名有关的代码已全部移除

### 配置文件位置

- MacWave：`/opt/macwave_config`
- LinuxWave：**`/etc/linuxwave_config`**（系统级，需 `sudo`）或 **`~/.config/linuxwave_config`**（用户级），读取时**系统级优先**

### 安装目录

- MacWave：前两项相同，第 3 项标注 “Only Intel Mac”
- LinuxWave：第 3 项 `/usr/local/linuxwave` **仅在 x86_64 上提供**（arm64 的菜单里没有这一项）

### 软件包

索引中的软件包已全部换成 **Linux 构建**（x86_64 取 `linux-64`，arm64 取 `linux-aarch64`），与 MacWave 的差异：

- **`ipsw` 与 `tmux` 升级到更新的版本**（`ipsw` 3.1.730 → **3.1.731**，`tmux` 3.3a → **3.6**）——这些版本当时没有 macOS 构建，但提供了 Linux 构建
- **移除 `choma` 与 `fileicon`**：二者没有 Linux 构建（`fileicon` 依赖 macOS 专有工具链，ChOma 只出 macOS/iOS 二进制）
- `htop`（**3.2.1**，MacWave 为 3.5.3）与 `ncdu`（**1.16**，MacWave 为 2.9.2）停留在较早版本：它们更新的 Linux 构建只以 `.conda` 形式发布，而这两个包沿用 `.tar.bz2` 的最后一个版本

## Differences from MacWave

### Target platform and dependency relocation

- MacWave handles **Mach-O** with **Xcode Command Line Tools** (`otool`, `install_name_tool`); LinuxWave handles **ELF** with **`patchelf`**
- Each ELF's `RUNPATH` is rewritten to **`$ORIGIN`-relative paths**: the artifact's own `lib/` and `lib64/`, then the directories of the dependencies it needs. Everything is relative, so **moving the whole install directory keeps working**
- **There is no code-signing step**: ELF does not enforce signing, so a relocated binary runs immediately. All signing-related code on the MacWave side has been removed

### Config file location

- MacWave: `/opt/macwave_config`
- LinuxWave: **`/etc/linuxwave_config`** (system-level, needs `sudo`) or **`~/.config/linuxwave_config`** (user-level), with the **system-level config winning** at read time

### Install directory

- MacWave: the first two entries match, and the third is labelled "Only Intel Mac"
- LinuxWave: the third, `/usr/local/linuxwave`, is offered **on x86_64 only** (it is absent from the arm64 menu)

### Packages

Every package in the index now points at a **Linux build** (`linux-64` on x86_64, `linux-aarch64` on arm64). Differences from MacWave:

- **`ipsw` and `tmux` moved to newer versions** (`ipsw` 3.1.730 → **3.1.731**, `tmux` 3.3a → **3.6**) - those releases had no macOS build but do ship Linux builds
- **`choma` and `fileicon` were dropped**: neither has a Linux build (`fileicon` drives macOS-only tooling, and ChOma only publishes macOS/iOS binaries)
- `htop` (**3.2.1**, versus MacWave's 3.5.3) and `ncdu` (**1.16**, versus 2.9.2) stay on earlier releases, because their newer Linux builds are published only as `.conda`

## 依赖重定位：patchelf

- 判定与写入都由 `patchelf` 完成，重复执行是**幂等**的（已是目标值就不再改写）
- 系统库有白名单（来自 `ldconfig -p` 加固定名单），**绝不覆盖或链到发行版自带的库**
- 未安装 `patchelf` 时安装器会给出警告与安装命令，此时依赖库无法重定位，部分软件包可能无法运行

## Dependency Relocation: patchelf

- Detection and rewriting are done by `patchelf`, and re-running is **idempotent** (a value already correct is left alone)
- System libraries are allow-listed (from `ldconfig -p` plus a fixed list), so LinuxWave **never overwrites or links against distribution libraries**
- When `patchelf` is missing the installer warns and prints the install command; without it dependency libraries cannot be relocated and some packages may fail to run

## 环境要求

- **Linux（x86_64 / arm64）**
- **Python 3.14 及以上**——`.bz2` / `.tar.bz2` / `.xz` / `.conda` 都用 Python 标准库解压，因此**不要求**系统装有 `bzip2`、`xz`、`zstd` 命令
- **patchelf**（用于依赖库重定位）

```
sudo apt install patchelf        # 或: sudo dnf install patchelf
```

## Requirements

## 其他改动

- 支持 **10 种归档格式**：无扩展名、`.zip`、`.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar`、`.gz`、`.xz`、`.bz2`、`.conda`
- 校验在前、解压在后：`sha256` 不匹配就不会解压
- 中断的下载可用 `-C` 续传
- 依赖按**引用计数**管理：卸载软件包时，只有再没有别的包依赖某个依赖，它才会被一并删除
- 无版本号软链接：`wave link <包>` 建立，安装/卸载版本时会自动改指最高的那个；`wave linkquery` 可查看当前指向，指向已不存在的版本会报错
- `wave uninstall` 会同时清理 `/etc/linuxwave_config` 与 `~/.config/linuxwave_config`，不留会让程序误判「已安装」的残留配置
- 配置读取更健壮：某一处配置损坏或缺少 `base_dir` 时，会自动尝试下一处，而不是直接报错退出

## Other Changes

- **10 archive formats** supported: no extension, `.zip`, `.tar.gz`, `.tar.bz2`, `.tar.xz`, `.tar`, `.gz`, `.xz`, `.bz2`, `.conda`
- Verify first, extract later: nothing is unpacked unless the `sha256` matches
- Interrupted downloads resume with `-C`
- Dependencies are **reference counted**: uninstalling a package removes a dependency only once nothing else needs it
- Versionless links: `wave link <package>` creates one and re-points it to the highest installed version on install/uninstall; `wave linkquery` shows where it points and errors if that version is gone
- `wave uninstall` cleans both `/etc/linuxwave_config` and `~/.config/linuxwave_config`, leaving no stale config that would make LinuxWave believe it is still installed
- Config loading is more robust: if one location is corrupted or missing `base_dir`, LinuxWave tries the next one instead of exiting with an error

## 提示

- **在 Linux 上用过 MacWave 的用户请重新安装**：LinuxWave 使用自己的配置目录，**不会读取 MacWave 的配置**，也不会复用 MacWave 安装的软件包（那些是 Mach-O 二进制，在 Linux 上本来也无法运行）
- 装完后重启终端，或执行 `source ~/.bashrc` 立即生效（zsh 用 `~/.zshrc`）
- `htop` 与 `ncdu` 的版本低于 MacWave 上的同名包，原因是如上所述的归档格式限制，不是索引错误
- `ldid` 等原本面向越狱场景的工具在 Linux 上同样可用，但它们操作的仍是 Mach-O 文件，与 LinuxWave 自身的 ELF 软件包互不影响

## Tips

- **Coming from MacWave on Linux? Reinstall.** LinuxWave uses its own config directories, does **not** read MacWave's configuration, and does not reuse packages installed by MacWave (those are Mach-O binaries that cannot run on Linux anyway).
- Restart your terminal afterwards, or run `source ~/.bashrc` to apply the change immediately (use `~/.zshrc` on zsh).
- `htop` and `ncdu` sit below the MacWave versions of the same packages; that is the archive-format limit described above, not an index error.
- Tools such as `ldid` remain available on Linux, but they still operate on Mach-O files; they are independent of LinuxWave's own ELF packages.

## Selfupdate更新

`wave selfupdate` 从 `configdata` 分支读取版本数据，并按其中的 `branch` 字段（当前为 `HEAD`）拉取代码文件，因此始终跟随默认分支。目录结构的变更由 `configdata/updatedata/{版本号}` 提供迁移脚本，`install.sh` 与 `selfupdate.sh` 都会执行。

## Selfupdate Update

`wave selfupdate` reads the version data from the `configdata` branch and fetches code files from the branch named in its `branch` field (currently `HEAD`), so it always follows the default branch. Directory-structure changes are migrated through scripts in `configdata/updatedata/{version}`, which both `install.sh` and `selfupdate.sh` run.
