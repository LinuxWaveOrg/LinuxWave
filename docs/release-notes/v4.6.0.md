# LinuxWave 4.6.0

**LinuxWave 4.6.0** · Build number: **328B1519** · Released **2026-11-24** · Release branch: `4.6`

4.6 is about **the install tree itself**: taking a lock before touching it, being able to
inspect it, being able to repair one package without upgrading anything, being able to move
it, and no longer keeping a second, always-stale copy of "what is installed". It also
finishes the move to Apache-2.0 that 4.6's MacWave counterpart started.

## Upgrading

`wave selfupdate` is enough. `4.5` and `4.6` share major version `4`:

```bash
wave selfupdate
```

The first self-update after this release will ask you to accept the agreement once more —
the licence changed (see section 7), and that counts as an agreement change.

## 1. Two `wave` runs can no longer write the tree at the same time

Installing, uninstalling and self-updating all rewrite `bin/`, `links/`, `.depped_*` counters
and `downloads/tmp`. Two of them running at once used to corrupt each other quietly: a
half-written version directory, a link pointing at the wrong version, a dependency deleted
while another package still needed it.

`4.6` takes an exclusive lock on the whole tree (`var/lock/wave.lock`, `flock`) for the
duration of those commands. It is:

- **released by the kernel** if the process dies (Ctrl-C, `SIGKILL`) — no stale lock file to
  delete by hand;
- **re-entrant** inside one process, so `wave upgrade --all`, a multi-package install and
  `wave reinstall` do not deadlock themselves;
- **fail-fast**: the second `wave` says who holds the lock and what it is doing, instead of
  waiting silently.

If the lock file cannot be created at all (read-only media, odd permissions) the command
warns and continues — no mutex is better than no `wave`.

## 2. `wave doctor`: a read-only check of the install tree

```
$ wave doctor
🌊 Checking links ...
🌊 links/gone points at something that is gone
🌊   fix: wave link gone
🌊 Doctor: 4 problem(s) found, 1 note(s).
```

Seven checks: `base-dir` (exists / writable), `tree` (the six component directories),
`installed` (a version directory without its executable, plus interrupted `.bak` leftovers),
`links` (dangling links, packages that were never linked), `dependencies` (a dependency tree
nobody references any more), `downloads` (abandoned `.partial` files — a note, not a
problem), `position` (ELF files whose `RPATH` still names an absolute path).

Nothing is changed. Every finding comes with the command that fixes it, the exit status is
the number of problems (so `wave doctor` works in a script), `--raw` gives one
`severity<TAB>check<TAB>detail` line per finding, and `--list-checks` lists the checks.
"Could not tell" (no `patchelf` / `readelf` / `objdump`) is reported as a note, never as a
broken package.

## 3. `wave reinstall`: the same version, again

```
$ wave reinstall jq
$ wave reinstall jq@1.8.2
$ wave reinstall --all
```

Useful when the mirror rebuilt a package under the same version number, when the tree was
damaged (it is the fix `wave doctor` suggests), or to pin a package back to the version you
already have instead of upgrading. The version always comes from disk — `--ver` is refused,
and a version that is not installed is refused with the list of versions that are.

## 4. `wave transfer`: make already-installed packages movable

Install-time relocation rewrites ELF `RPATH` to `$ORIGIN`. Packages installed before that
happened — or while `patchelf` was missing — may still name an absolute path, and then moving
the tree breaks them. `wave transfer` fixes those in place:

```
$ wave transfer --all --dry-run     # what would change
$ wave transfer --all              # do it
```

Each artifact is checked first (`transfer.sh --check`, read-only): already relative → skipped,
absolute → rewritten, "cannot tell" → reported as a failure. Dependencies pulled in by the
named packages are transferred too. Safe to repeat.

## 5. `wave basedir --set`: move the whole tree

```
$ wave basedir --set ~/apps/linuxwave
```

Copies the tree, rewrites `base_dir`, re-checks the private environment, and prints the one
line your shell rc needs. Three typed confirmations are required (`Yes`, the current path,
and a sentence containing the new path); `-n/--dry-run` reports without touching anything.
The old tree is **not** deleted — that is yours to do once you are happy.

## 6. No more `pkg/installed.json`

Every record in it could be derived from `bin/<name>@<version>/`, and it was the only file
that could disagree with the disk. It is gone; `wave list` and `wave uninstall` scan the
directory, as they always effectively did.

Also in this release: `downloads/tmp` cleans up `.partial` files untouched for more than
7 days whenever you install or uninstall, and says what it removed.

## 7. Licence: Apache-2.0 from 4.6.0

`LICENSE` is now Apache-2.0 (with a `NOTICE`), and `info/` carries the same two files into the
install tree. Nothing is retroactive: **1.0.0 – 4.5.2 were published under MIT and stay under
MIT**. That boundary is why this release asks you to accept the agreement again; the
agreement text and its date are on <https://linuxwave.org>.

## 8. Known limitations

- **No `min_os` equivalent.** Linux has no Mach-O `minos`; a package needing a newer glibc
  fails at run time.
- `wave basedir --set` does not edit your shell rc — it prints the line to put there.
- The lock is advisory: it coordinates `wave` processes, not a human with `rm -rf`.

# LinuxWave 4.6.0

**LinuxWave 4.6.0** · 构建号：**328B1519** · 发布于 **2026-11-24** · 发布分支：`4.6`

4.6 讲的是**安装树本身**：动它之前先上锁、能对它做体检、能只修一个包而不升级、能把它
整体搬走，以及不再另存一份「装了什么」——那份副本永远比磁盘旧。顺带把 MacWave 那条线
上已经开始的 Apache-2.0 迁移做完。

## 升级方式

`wave selfupdate` 就够。`4.5` 与 `4.6` 主版本号都是 `4`：

```bash
wave selfupdate
```

这一版之后的第一次自更新会再问一次协议 —— 许可证变了（见第 7 节），那算协议变更。

## 1. 两个 wave 不会再同时写同一棵树

装包、卸载、自更新都会重写 `bin/`、`links/`、`.depped_*` 计数与 `downloads/tmp`。以前
两个同时跑会安静地互相破坏：写了一半的版本目录、指错版本的链接、还有人在用却被删掉的
依赖。

4.6 在这些命令执行期间对整棵树加排他锁（`var/lock/wave.lock`，`flock`）：

- **进程死掉由内核释放**（Ctrl-C、`SIGKILL` 都是），不会留下要手删的死锁文件；
- **同一进程内可重入**，所以 `wave upgrade --all`、多包安装、`wave reinstall` 不会自锁；
- **失败即说清**：第二个 wave 会报出谁持有锁、正在做什么，而不是默默排队。

如果锁文件根本建不出来（只读介质、权限异常），命令会警告后继续 —— 没有互斥也比没有
`wave` 强。

## 2. `wave doctor`：安装树的只读体检

七项：`base-dir`（存在/可写）、`tree`（六个组件目录）、`installed`（版本目录里没有可
执行文件、中断留下的 `.bak`）、`links`（悬空链接、装了却没链接）、`dependencies`
（没人引用的依赖树）、`downloads`（没下完的 `.partial`，只算提醒）、`position`（RPATH
里还写着绝对路径的 ELF）。

什么都不会改。每条发现都附上该跑哪条命令；退出码是问题数（可以进脚本）；`--raw` 每条
发现一行 `严重程度<TAB>检查项<TAB>说明`；`--list-checks` 列出检查项。「判断不了」
（没有 `patchelf` / `readelf` / `objdump`）只记提醒，绝不把包报成坏的。

## 3. `wave reinstall`：同一个版本，再来一遍

镜像重出了同一个版本号、安装树被改坏（`wave doctor` 给的就是这条命令）、或者想把包按回
已装版本而不升级时用。版本永远来自磁盘 —— 不接受 `--ver`，指定没装的版本会被拒绝并列出
装着的版本。

## 4. `wave transfer`：让已装的包可以被搬走

安装时的重定位会把 ELF 的 RPATH 改成 `$ORIGIN`。在那之前装的、或者当时缺 `patchelf`
被跳过的包，RPATH 里可能还留着绝对路径，一搬家就跑不起来。`wave transfer` 就地补上：

```
$ wave transfer --all --dry-run     # 看会改哪些
$ wave transfer --all              # 动手
```

每个产物先跑 `transfer.sh --check`（只读）：已是相对 → 跳过；有绝对路径 → 改写；判断
不了 → 记为失败并说明。被点名的包用到的依赖也一起改。可以反复跑。

## 5. `wave basedir --set`：整棵树换位置

复制整棵树、改写 `base_dir`、复查私有环境，并打印你 shell rc 需要换的那一行。要求三段
逐字确认（`Yes`、当前路径、含新路径的一句话）；`-n/--dry-run` 只报告不动手。旧树
**不会**被删 —— 确认无误后你自己删。

## 6. 不再有 `pkg/installed.json`

里面每一条都能从 `bin/<名>@<版本>/` 推导，而它是唯一可能与磁盘不一致的文件。删掉了；
`wave list` 与 `wave uninstall` 直接扫目录（它们本来也是这么判断的）。

另外：`install` / `uninstall` 时会顺手清掉 `downloads/tmp` 里超过 7 天没动过的
`.partial`，并说明清掉了什么。

## 7. 许可证：4.6.0 起 Apache-2.0

`LICENSE` 换成 Apache-2.0（另有 `NOTICE`），`info/` 把同样两份随安装树下发。**不追溯**：
1.0.0 – 4.5.2 是按 MIT 发布的，继续按 MIT 算。这条界线正是这一版要重新询问协议的原因；
协议正文与落款见 <https://linuxwave.org>。

## 8. 已知限制

- **没有 `min_os` 的等价物。** Linux 没有 Mach-O 的 `minos`，需要更新 glibc 的包会在
  运行时失败。
- `wave basedir --set` 不替你改 shell rc —— 它只把该写的那一行打印出来。
- 这把锁是协作性的：它协调的是 `wave` 进程，不是手拿 `rm -rf` 的人。
