# 重要更新

**LinuxWave 4.0.0** · Build number: **324E1459** · 发布于 **2026-11-20** · 发布分支：`4.0`

> **必须用安装器升级。** 4.0 是跨大版本，`wave selfupdate` 会拒绝（规则在脚本里，不在数据里）。
> 一条命令重装，已装的软件包不会被动：
>
> ```bash
> /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/LinuxWaveOrg/LinuxWave/4.0/lib/install.sh)"
> ```

## 为什么要升级

4.0 是一次**结构换代**，不是加功能。三件积攒了两年的事在这一版一起做完：

1. **「要装哪些文件」不再由客户端猜。** 3.x 的客户端去 `configdata` 拉一份 `files_info` 缩进树，
   用自带的 `python3` 解析，再逐文件下载。清单与代码分处两个仓库、由人工同步，
   漏一行的症状是装完之后某条命令 `ModuleNotFoundError`（3.1.0 就漏过三行）。
2. **命令的定义散在四个地方。** 命令表、帮助文本、`if/elif` 分发链、README 各写一份，
   删一条命令要改三处，漏一处的症状是「帮助里挂着、敲下去是 unknown command」——
   从 1.x 一直残留到 2.3.1 才被发现。
3. **超时只有一档。** `--connect-timeout` / `--content-time` 在 Python 侧与 `--max-time`
   挤进同一个 socket 超时里，shell 侧每个 `curl` 只认一个 `--max-time`。

## 环境要求（变了）

| 项 | 要求 |
| --- | --- |
| 系统 | Linux（x86_64 / arm64） |
| shell | **bash 4.4+**（安装器与自更新脚本都用到较新的展开语法；低于 4.4 会在开头就明确报错，不会跑到一半才炸） |
| 共享安装 | 需要免密 `sudo` 或 root（建 `linuxwave` 账号、写 `/etc/linuxwave_config`）；用户级安装不需要 |

macOS 请用 [MacWave](https://macwave.org)。

## 这一版做了什么

### 1. 安装清单换代：`latest.toml` + 按版本冻结的 `update_commands.sh`

自更新数据从「一份缩进树」变成两级结构：

```
linuxwavedata/latest.toml                 哪个版本是最新的（每次发版都变）
linuxwavedata/<版本>/update_commands.sh    那一版具体怎么装（发版后不再变）
```

拆开的理由：装了旧版本的用户仍在运行，他们那份更新说明不能因为发了新版就变样。

- 清单在发版时由 `scripts/build_update_commands.py` **内联**进脚本，来源是仓库里的
  `scripts/components.txt` + `scripts/assets.txt`；每行带 sha256（4.0 是实验期，只警告）
- 脚本自己决定全量还是增量：首次安装、树不完整、`LINUXWAVE_FULL_INSTALL=1` 走全量；
  其余走增量，之后再补一次全量兜住跨版本跳级
- 判断「树完整吗」用 `FULL_FILES`（本版应有的全部文件），不是「`lib/wave.py` 在不在」——
  后者会把「上一版留下的一半升级」「被手工删过文件的树」都当成好树，于是永远停在
  `Already at`，跑多少次都修不好
- **`VERSION.json` 只在脚本成功执行完之后才写**。先写凭据、后下载，中途失败会留下
  「版本号前进、文件还是旧的」——`wave selfupdate` 比完版本号就说已是最新，永远不会再修
- 目录结构变更的**迁移写在同一个脚本里**（本版：删掉旧树 `lib/` 下的
  `domains.py` / `configpaths.py` / `configerror.py` / `help.py` / `silent.py` / `quiet.py`）。
  `configdata` 的 `updatedata/`（`dir_structure_change` + `transfer_commands`）随之退休
- 3.x 的 `versiondata/latest_version` 回落**整段删除**：探针读不到就是读不到，不再有两套真相

### 2. 程序分层：`cli/ config/ lib/ net/ pkg/ surfboard/`

```
cli/          命令行层（命令表、旗标、帮助、静默、手册、纠错建议）
config/       配置与环境变量（configpaths、configerror、envvar）
lib/          入口与自更新（wave、selfupdate、shellenv、latest、steplog、versioncompare）
net/          传输层（domains、tls、timeouts、signature）
pkg/          安装与查询核心
surfboard/    依赖处理
Keys/         发布签名公钥（资源目录，不进 sys.path）
```

- `scripts/components.txt` 是「哪些目录参与运行」的**唯一来源**：安装清单的内联、`lib/wave.py`
  的 `sys.path`、测试沙箱的拷贝、CI 的工作目录都读它
- `scripts/assets.txt` 是资源目录（`Keys/`）：装进安装树，但**不进** `sys.path`
- `scripts/structure_test.sh` 盯住「清单里有、某处没准备」的所有组合，以及「又有人手写了一份
  三连清单」

### 3. 命令层表驱动

`cli/commands.py` 成为命令的唯一定义处：一条命令的名字、模块、处理函数、一句话说明、
用法、旗标、示例都在那里。`wave -h`、`wave <cmd> --help`、分发、`wave manual`、README 的
命令表全部从它生成。

- 分发不再有 `if/elif` 链：`commands.get(name)` → `importlib` → 调用
- 未知命令给**建议**（`Did you mean: wave install`），并把命令行原样回显、用 `^` 指住错处；
  拼错的旗标不会被抄进建议里
- 旗标白名单统一走 `cli/common.py` 的 `check_allowed()`：`illegal option X for wave install`
  + `you ran:` + 指针 + 候选（只从本命令的白名单里取）。以前同一类错误有三种说法，
  `wave uninstall --ver=1.0` 甚至只打一行警告然后照旧执行
- 静默（`-s` / `-S`）由 `cli/silent.py` 一处决定：剥旗标、写运行期开关、静默下的错误只用一行
- `wave manual` 在终端里直接看手册（不依赖 `man` / `info` 是否装好），默认纯文本、`--zh` 中文

### 4. 新增 `wave latest`

看某个（或全部）已装包有没有新版本，只报告、不下载。打错包名时给出最像的那个，
并且分清三种「查不到」：名字不在索引里、名字在但没出版本清单、连清单都读不到（网络/证书）。

### 5. 三档超时一路到 `curl`

```
wave selfupdate --connect-timeout=10s --content-time=15s --max-time=2min
  ↓ cli/common.py parse()          校验 + 换算
  ↓ common.export_timeouts()       原始文本 → LINUXWAVE_* 环境变量
  ↓ lib/selfupdate.sh lw_seconds() 变成 curl 旗标
curl --max-time 120 --connect-timeout 10 --speed-limit 1 --speed-time 15 …
```

- 传文本而不是秒：换算规则只有 `net/timeouts.py` 一份
- `250ms` 这类小于一秒的值向上取整到 1 秒（以前会算出 0.001，传给 curl 等于不限时）

### 6. 协议更新后先征得同意

安装器一直会把「同意的是哪一版协议」写进 `AGREEMENT.json`，但以前的 `selfupdate.py`
只定义 `AGREEMENT_ID`、从不读它 —— 改协议对老用户等于无效。现在：

- 记录 == 当前 `AGREEMENT_ID` → 不问
- 记录缺失/过期、且已装版本 ≤ 4.0.0（协议引入版）→ 问一次
- 只有明确 `y/Y` 才继续；空回车、EOF、`yes` 都按拒绝处理，拒绝时一个字节都不动
- 静默模式（`-s`）不能替用户同意：提示写 `/dev/tty`，按未同意退出
- 跨大版本不问（那次更新本来就要重装）；`--dry-run` 不问也不记录

### 7. 安装器

- 目录菜单重排：共享安装 `/home/linuxwave/.linuxwave` 升为第 **1** 项（推荐），其余顺延
- `--ci`（原 `-S` / `--silent` 更名）、`--dry-run`、`--raw`、`--zh`、`--skip-probe`、
  `--skip-platform-check`、`--dir-option=N[=DIR]`、`--print-usage`
- `--help` 只允许单独或与 `--dry-run` 连用；帮助里可复制的路径按 shell 规则加引号
- 应答归一化：空 / `y` / `yes` → 同意；`n` / `no` → 拒绝；其它重新提问，最多 3 次
- 回滚只在「这棵树是本次建的」时才删（`TREE_PREEXISTED`）：覆盖升级时拒绝协议不再毁掉用户已有的安装
- 许可协议在「安装完成」**之前**询问；拒绝时把安装树、配置目录与 rc 里的 PATH 一起回滚干净
- `--no-link`（旧名 `--unlink` 仍可用）：不创建/不改动不带版本号的链接
- 共享安装的组共享、`newgrp` 提示、属主交还等行为保持不变

### 8. `wave shellenv`

rc 文件里只写**一行** `eval "$(<安装根>/lib/wave shellenv)"`。以前写的是整行 `export PATH=…`，
升级换目录或卸载时都得去猜用户文件里哪行是自己写的。旧版写过 `export PATH=` 的，
安装结束时会打印删除命令并说明理由，但不替用户删。

### 9. 镜像站

- 每个对外地址都可由环境变量覆盖：`LINUXWAVE_{API,BOTTLE,DEPS,CORE,PYTHON,SELFUPDATE}_DOMAIN`，
  外加 `LINUXWAVE_CACERT`（企业网络里 TLS 被重签、或自建镜像用私有 CA）
- `scripts/mirror_sync.sh`：把一个镜像根同步成 `<Org>/<repo>/<ref>/…` 的形状，并生成
  `pkg/pkginfo_<arch>/versions` 索引
- `docs/mirror.md`：nginx 的 `alias` + `^~` 前缀写法、为什么不能用 `^~ /MacWave/` 这种短前缀、
  产物域为什么要保留认证
- 报错与日志里的地址一律过一遍脱敏（`user:***@host`），因为镜像地址可能带凭据

### 10. 内部整理

- 前缀统一：`mw_*` → `lw_*`、`MW_*` → `LW_*`
- 错误/提示文案双语（`lw_say "<English>" "<中文>"`），`--zh` 与 `--raw` 全程生效
- 删掉从未被执行过的 `lib/help.py`（`import help` 一直命中 `cli/help.py`）

## 已知限制

- **必须用安装器升级**：跨大版本 `wave selfupdate` 会拒绝并指向安装命令
- **发布签名仍是实验期**：`LINUXWAVE_RSA_PUB` 未内置（仓库里的 `Keys/` 只有说明），
  验签整段跳过；清单里的逐文件 sha256 只警告，`LINUXWAVE_STRICT_HASHES=1` 才强制
- **`wave info --json/--yaml/--toml` 与 `wave upgrade --all` 尚未移植**：帮助里写了，
  但实现在下一版补齐（该两项在 `cli/commands.py` 里已被标记，`scripts/commands_test.sh`
  会盯住「帮助承诺了、handler 没实现」以外的部分）
- **镜像站需要按新布局同步**：LinuxWave 侧的镜像目录还没切到 `<Org>/<repo>/<ref>/…`；
  切换前自更新会 404（脚本会明确提示「镜像还没同步这个分支」）
- `wave install` 的 `--install-from-source` 仍然保留，但与 4.0 的「只从自有存储取」方向不一致，
  下一版会重新评估

# Major update

**LinuxWave 4.0.0** · Build number: **324E1459** · Released **2026-11-20** · Branch: `4.0`

> **Reinstall with the installer.** 4.0 is a new major version, so `wave selfupdate` refuses it
> (the rule lives in the script, not in the data). One command reinstalls; installed packages are
> left alone:
>
> ```bash
> /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/LinuxWaveOrg/LinuxWave/4.0/lib/install.sh)"
> ```

## Why upgrade

4.0 is a structural change rather than a feature release. Three long-standing problems are fixed
at once:

1. **The client no longer guesses which files to install.** 3.x fetched a `files_info` indent tree
   from `configdata`, parsed it with its bundled `python3`, then downloaded every file one by one.
   The list and the code lived in different repositories and were kept in sync by hand; a missed
   line surfaced as `ModuleNotFoundError` after the install finished (3.1.0 missed three).
2. **Commands were defined in four places.** The dispatch table, the help text, the `if/elif`
   chain and the README each had their own copy. Deleting a command meant editing three of them,
   and the failure mode was a zombie entry in `wave -h` that no one noticed (1.x → 2.3.1).
3. **Only one timeout existed.** `--connect-timeout` / `--content-time` were folded into the same
   socket timeout as `--max-time` on the Python side, and every shell `curl` knew a single
   `--max-time`.

## Requirements (changed)

| Item | Requirement |
| --- | --- |
| System | Linux (x86_64 / arm64) |
| Shell | **bash 4.4+** — the installer and the updater use newer expansions; older shells are rejected up front instead of failing halfway |
| Shared install | passwordless `sudo` (or root) to create the `linuxwave` account and write `/etc/linuxwave_config`; a per-user install needs neither |

macOS users want [MacWave](https://macwave.org).

## What this release does

### 1. The manifest moved into a per-release script

The self-update data is now two levels:

```
linuxwavedata/latest.toml                 which version is current (changes every release)
linuxwavedata/<version>/update_commands.sh how that version is installed (frozen)
```

They are split for a reason: users still running an older version must keep the instructions that
matched *their* version.

- The manifest is inlined at release time by `scripts/build_update_commands.py`, sourced from
  `scripts/components.txt` + `scripts/assets.txt`, one line per file with its sha256
  (experimental in 4.0: warn only)
- The script decides full vs delta by itself: fresh installs, incomplete trees and
  `LINUXWAVE_FULL_INSTALL=1` take the full list; everything else takes the delta and then
  re-checks, which also covers version jumps
- "Is the tree complete" is answered by `FULL_FILES` (every file this version should have), not by
  "does `lib/wave.py` exist" — the latter treats half-finished upgrades and hand-damaged trees as
  healthy, so they sit at `Already at` forever
- **`VERSION.json` is written only after the script succeeds.** Writing it first and downloading
  second leaves "version bumped, files still old", which `wave selfupdate` will never repair
- Layout migrations live in the same script (4.0 removes the stale `lib/` copies of
  `domains.py`, `configpaths.py`, `configerror.py`, `help.py`, `silent.py`, `quiet.py`), so
  `configdata/updatedata/` and its `dir_structure_change` / `transfer_commands` pair are retired
- The 3.x fallback to `versiondata/latest_version` is **gone**: one source of truth

### 2. Layered program tree

```
cli/          command line (table, flags, help, silence, manual, suggestions)
config/       configuration and environment variables
lib/          entry point and self-update
net/          transport (domains, tls, timeouts, signature)
pkg/          install and query core
surfboard/    dependency handling
Keys/         signing key (asset directory, not on sys.path)
```

- `scripts/components.txt` is the single source for "which directories run": the inlined manifest,
  `lib/wave.py`'s `sys.path`, the test sandbox and the CI working directory all read it
- `scripts/assets.txt` lists asset directories (`Keys/`): installed, but never imported
- `scripts/structure_test.sh` fails when a component is missing somewhere, or when someone
  hand-writes a second list

### 3. Table-driven commands

`cli/commands.py` is the only definition of a command: name, module, handler, summary, usage,
flags and examples. `wave -h`, `wave <cmd> --help`, dispatch, `wave manual` and the README command
table are all generated from it.

- No `if/elif` chain: `commands.get(name)` → `importlib` → call
- Unknown commands get a suggestion, the command line is echoed back and the offending word is
  underlined with `^`; mistyped flags are kept out of the suggestion
- Flag whitelists go through `cli/common.py`'s `check_allowed()`:
  `illegal option X for wave install` + `you ran:` + pointer + candidate (only from this
  command's whitelist). Previously the same mistake had three different wordings, and
  `wave uninstall --ver=1.0` printed a warning and carried on
- Silence (`-s` / `-S`) is decided in one place (`cli/silent.py`)
- `wave manual` renders the manual in the terminal, independent of `man` / `info`

### 4. New `wave latest`

Shows whether installed packages have a newer version; nothing is downloaded. A mistyped package
name gets the closest match, and three "not found" cases are distinguished: name not in the index,
name present but no version list, and the index itself unreachable (network / certificate).

### 5. Three-tier timeouts all the way to `curl`

```
wave selfupdate --connect-timeout=10s --content-time=15s --max-time=2min
  ↓ cli/common.py parse()          validated and converted
  ↓ common.export_timeouts()       raw text → LINUXWAVE_* environment
  ↓ lib/selfupdate.sh lw_seconds() becomes curl flags
curl --max-time 120 --connect-timeout 10 --speed-limit 1 --speed-time 15 …
```

- Raw text is passed, not seconds: the conversion lives only in `net/timeouts.py`
- Sub-second values such as `250ms` round up to 1 second (previously `0.001`, i.e. "no limit")

### 6. Consent before a changed agreement

The installer has always recorded which agreement version the user accepted, but `selfupdate.py`
only defined `AGREEMENT_ID` and never read it — so a changed agreement had no effect on existing
users. Now:

- recorded value == current `AGREEMENT_ID` → do not ask
- missing/stale record and installed version ≤ 4.0.0 (the version that introduced the agreement)
  → ask once
- only an explicit `y/Y` continues; empty input, EOF and `yes` all count as refusal, and a refusal
  changes nothing on disk
- silent mode cannot consent on the user's behalf: the message goes to `/dev/tty` and it exits
  as "not accepted"
- cross-major updates do not ask (those need a reinstall anyway); `--dry-run` neither asks nor
  records

### 7. Installer

- Menu reordered: the shared install `/home/linuxwave/.linuxwave` is entry **1** (recommended)
- `--ci` (renamed from `-S` / `--silent`), `--dry-run`, `--raw`, `--zh`, `--skip-probe`,
  `--skip-platform-check`, `--dir-option=N[=DIR]`, `--print-usage`
- `--help` may only be used alone or with `--dry-run`; copyable paths are quoted per shell rules
- Answers are normalised: empty / `y` / `yes` accept; `n` / `no` refuse; anything else asks again,
  at most three times
- Rollback removes the tree only when this run created it (`TREE_PREEXISTED`), so refusing the
  agreement during an upgrade no longer destroys a working install
- The agreement is asked **before** "installation complete"; refusing rolls back the tree, the
  config directory and the PATH line
- `--no-link` (old name `--unlink` still accepted) skips the unversioned link

### 8. `wave shellenv`

The rc file gets a single line: `eval "$(<base>/lib/wave shellenv)"`. Previously it was a full
`export PATH=…`, which made upgrades and uninstalls guess which line belonged to LinuxWave.
Installations that still carry the old line are told how to remove it.

### 9. Mirrors

- Every outbound address can be overridden: `LINUXWAVE_{API,BOTTLE,DEPS,CORE,PYTHON,SELFUPDATE}_DOMAIN`,
  plus `LINUXWAVE_CACERT` for enterprise TLS interception and private CAs
- `scripts/mirror_sync.sh` lays out a mirror as `<Org>/<repo>/<ref>/…` and generates
  `pkg/pkginfo_<arch>/versions` indexes
- `docs/mirror.md` documents the nginx `alias` + `^~` setup, why short prefixes steal payload
  paths, and why the payload domains keep authentication
- Addresses in errors and logs are redacted (`user:***@host`) because mirror URLs can carry
  credentials

### 10. Internal clean-up

- Prefixes unified: `mw_*` → `lw_*`, `MW_*` → `LW_*`
- Bilingual messages via `lw_say "<English>" "<中文>"`, honouring `--zh` and `--raw`
- Removed the never-executed `lib/help.py` (`import help` always resolved to `cli/help.py`)

## Known limitations

- **Upgrade with the installer**: cross-major `wave selfupdate` refuses and points at the command
- **Signing is still experimental**: no `LINUXWAVE_RSA_PUB` is embedded (the repo's `Keys/` holds
  documentation only), so verification is skipped; per-file sha256 in the manifest only warns
  unless `LINUXWAVE_STRICT_HASHES=1`
- **`wave info --json/--yaml/--toml` and `wave upgrade --all` are not ported yet**; the next
  release fills them in
- **Mirrors need to be re-laid-out**: the LinuxWave mirror does not yet use
  `<Org>/<repo>/<ref>/…`; until it does, self-update fails with an explicit "the mirror has not
  synced this branch" message
- `wave install --install-from-source` still exists, which does not match 4.0's "own store only"
  direction; it will be re-evaluated next release

# Install 安装

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/LinuxWaveOrg/LinuxWave/4.0/lib/install.sh)"
```

**Do not** use `bash -c "$(curl …)"` (the whole script becomes a single argument and can exceed the
131 071-byte limit) and **do not** prefix it with `sudo` (sudo resets the environment and bypasses
the installer's own privilege handling). To pass flags, write `--` first:

```bash
curl -fsSL <url> | /bin/bash -s -- --ci --dir-option=2
```
