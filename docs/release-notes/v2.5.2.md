# Release Note 更新日志

## 新增：无人值守安装与卸载

为批量部署与脚本调用，安装器与卸载器都增加了参数，**全程无需任何交互**。

### 安装

```
--silent, -S              不进行任何交互：目录菜单与许可协议都自动应答
--dir-option=N            直接选择菜单项 N（1-5），不弹出菜单
--dir-option=N=DIR        选择菜单项 N；自定义项（5）直接用 DIR 作为安装目录
--help                    列出全部选项
```

示例：

```
# 脚本已在本地
bash install.sh --silent --dir-option=4

# 直接从仓库安装
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Sha0huaZhang/LinuxWave/HEAD/lib/install.sh)" \
  -- --silent --dir-option=4
```

`--silent` 在需要提权时会先检查能否免密 sudo；不能则**明确报错退出**，而不是停下来等一个没人看的密码提示。

> **用 `/bin/bash -c` 取脚本，选项放在 `--` 之后。** `/bin/bash` 的绝对路径不受被篡改的 `PATH` 影响，且 `curl` 会先完整结束、`bash` 才开始执行，下载中途失败不会被边下边跑。`--` 结束 bash 自身的选项，其后的参数才会传进安装器；写成 `… --silent` 会让 `--silent` 变成脚本名（`$0`）而被**静默丢弃**——安装器检测到这种用法时会给出警告。

### 卸载

```
--force          跳过全部确认；删除 LinuxWave 及其配置，但**保留** linuxwave 账号
--remove-user    连 linuxwave 账号一并删除（会连带删除家目录），不再询问
--help           列出全部选项
```

把"删除账号"拆成独立参数，是为了让**破坏性操作保持显式**，不被 `--force` 顺带执行。

## New: Unattended Install and Uninstall

Both scripts now take flags for batch deployment and scripting, with no interaction at all.

### Install

```
--silent, -S              No interaction: the directory menu and the agreement are answered automatically
--dir-option=N            Pick menu entry N (1-5) without showing the menu
--dir-option=N=DIR        Pick entry N; for the custom entry (5), install into DIR
--help                    List every option
```

```
# script already on disk
bash install.sh --silent --dir-option=4

# straight from the repository
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Sha0huaZhang/LinuxWave/HEAD/lib/install.sh)" \
  -- --silent --dir-option=4
```

When privilege is needed, `--silent` first checks that sudo can run without a password and **fails clearly** if it cannot, instead of stopping at a prompt nobody is watching.

> **Fetch with `/bin/bash -c`, and put options after `--`.** The absolute path keeps a tampered `PATH` from deciding which shell runs the script, and `curl` finishes before `bash` executes anything, so a download that fails partway is not executed as it arrives. `--` ends bash's own options, so the options after it reach the installer; writing `… --silent` makes `--silent` the script name (`$0`) and **silently drops it**.

### Uninstall

```
--force          Skip every confirmation; remove LinuxWave and its config, but KEEP the linuxwave account
--remove-user    Also delete the linuxwave account (and its home directory), without asking
--help           List every option
```

Removing the account is a separate flag so that a destructive step stays explicit rather than riding along with `--force`.

## 修复：卸载时删除账号会静默失败

上一个版本的卸载器在删除 `linuxwave` 账号时有两个问题，均由一次真实卸载暴露。

**问题一：失败了却报告成功。** 输出是：

```
userdel：用户 linuxwave 当前被进程使用 107119
🌊 User 'linuxwave' removed.        ← 并不属实
```

原因是脚本没有检查 `userdel` 的退出码。而失败本身很常见：**用户一旦建立过会话，systemd 就会为它启动一个 user manager**（本例中是 `systemd --user`），`userdel` 会因此拒绝删除。

现在会先 `loginctl disable-linger` 并停掉 `user@<uid>.service`，再执行 `userdel`；并检查退出码——失败时打印真实原因、给出可手工执行的命令，**退出码为 1**。

**问题二：漏清一份配置。** 卸载器只清理调用者家目录里的 `~/.config/linuxwave_config`，没有清理**共享用户自己**家目录里的那一份。当安装时 `HOME` 指向共享用户（`sudo HOME=/home/linuxwave ...`），用户级配置就写在那里，于是被留了下来。现在会一并清理。

**顺带修的第三处：** 若配置已被上一次卸载清掉、只剩共享安装树，卸载器现在仍会**从残留物识别出这是共享安装**（否则既不会提示删除账号，也不会清理那棵树），并把该树加入待删列表，使两处判断保持一致。

## Fix: Removing the Account Failed Silently

Two defects in the previous uninstaller, both surfaced by a real uninstall.

**It reported success on failure.** The output was:

```
userdel: user linuxwave is currently used by process 107119
🌊 User 'linuxwave' removed.        ← not true
```

The exit status of `userdel` was never checked. The failure itself is common: **once an account has had a session, systemd starts a user manager for it** (`systemd --user` in this case), and `userdel` refuses while it is in use.

The script now disables lingering, stops `user@<uid>.service`, then runs `userdel` and checks the result - printing the real reason and the manual commands on failure, and **exiting 1**.

**It missed one config file.** Only the caller's `~/.config/linuxwave_config` was cleaned, not the copy in the **shared user's own** home. When the install ran with `HOME` pointed at that user (`sudo HOME=/home/linuxwave ...`), the user-level config landed there and was left behind. It is now removed too.

**A third, related fix:** if the config is already gone and only the shared tree remains, the uninstaller now still recognises the shared install from what is left - otherwise it would neither offer to remove the account nor clean that tree - and adds the tree to the deletion list so both decisions agree.

## 修复：按官方写法卸载会删掉 `/bin/bash`

文档给出的卸载命令一直是 `/bin/bash -c "$(curl -fsSL ...)"`。在这种调用方式下，`$0` **不是脚本路径**，而是解释器自身；带参数时则是 `--`：

```
/bin/bash -c "$(curl ...)"              →  $0=/bin/bash  →  收尾执行 rm -f /bin/bash
/bin/bash -c "$(curl ...)" -- --force   →  $0=--         →  收尾执行 rm -f --（missing operand）
```

而卸载器收尾有一句 `rm -f "$0"`，本意是删掉刚刚下载下来的脚本。于是**按官方文档卸载、并且用了 sudo 的话，会把系统的 `/bin/bash` 删掉**——此后任何 `#!/bin/bash` 脚本都再也跑不起来。

现在只有当 `$0` 确实是**一个含本脚本标记的普通文件**时才自删；`$0` 是解释器路径、`--`，或是不含标记的其它文件时一律跳过。以文件方式运行（`bash uninstall.sh`）仍然和以前一样删除自己。

同一来源的还有一处措辞问题：安装/卸载器里那句提示原本教人用 `curl … | bash -s --`，现已改为 `/bin/bash -c "$(curl …)" -- <选项>`——绝对路径的 `/bin/bash` 不受被篡改的 `PATH` 影响，`curl` 也会先完整结束再由 `bash` 执行，下载中途失败不会被边下边跑。

## Fix: the Documented Uninstall Command Deleted /bin/bash

The uninstall command in the documentation has always been `/bin/bash -c "$(curl -fsSL ...)"`. Under that invocation `$0` is **not the script path** but the interpreter itself, or `--` when arguments follow:

```
/bin/bash -c "$(curl ...)"              →  $0=/bin/bash  →  ends with rm -f /bin/bash
/bin/bash -c "$(curl ...)" -- --force   →  $0=--         →  ends with rm -f --  (missing operand)
```

The uninstaller ended with `rm -f "$0"`, there to remove the script it had just downloaded. So **uninstalling the documented way, with sudo, deleted the system's `/bin/bash`** - after which no `#!/bin/bash` script could run again.

The self-delete now happens only when `$0` is **a regular file carrying this script's marker**; an interpreter path, `--`, or an unrelated file is left alone. Running it as a file (`bash uninstall.sh`) still removes itself exactly as before.

One wording fix from the same source: the hint printed by both scripts used to recommend `curl … | bash -s --`; it now recommends `/bin/bash -c "$(curl …)" -- <options>`, where the absolute path keeps a tampered `PATH` out of the picture and `curl` finishes before `bash` runs anything.

## 提示

- `--force` **不会**删除 `linuxwave` 账号；要删除请显式加 `--remove-user`，它会连带删除 `/home/linuxwave` 及其中的全部内容。

- 需要在 CI 中使用时，请为运行用户配置免密 sudo，或直接以 root 运行。

## Tips

- `--force` does **not** delete the `linuxwave` account; add `--remove-user` explicitly. That deletes `/home/linuxwave` and everything in it.
- `--silent` removes the interaction, not the output: progress and results are still printed so a log remains.
- For CI, give the running user passwordless sudo, or run as root.
