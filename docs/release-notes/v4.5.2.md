# LinuxWave 4.5.2

**LinuxWave 4.5.2** · Build number: **328B1254** · Released **2026-11-24** · Release branch: `4.5`

This release catches LinuxWave up with MacWave 4.5.2 — the code line these files are ported
from. Three things come with it: a package may now be a whole directory instead of one
executable, `install` and `uninstall` take lists, and an interrupted install of a tree
package no longer leaves the package permanently un-installable. `wave basedir` arrives too,
plus one piece LinuxWave has that MacWave does not ship until 4.6: `downloads/tmp` cleans up
after itself.

## Upgrading

`wave selfupdate` is enough. `4.4` and `4.5` share major version `4`, so this is not a
cross-major update and the installer is not needed:

```bash
wave selfupdate
```

## 1. A package can now be a tree

Some tools are not one file. `git` needs `libexec/git-core/git-remote-https` and
`share/git-core/templates`; neovim and helix need `runtime/`. A version record may now say:

```
install: "tree"
```

The installer then keeps the whole extracted directory under `bin/<name>@<version>/`, writes
a `.is_a_tree` marker, and links **every executable in `bin/`** — not just the main command,
because `git-upload-pack`, `dtc`'s `fdtget` and `testdisk`'s `photorec` are commands of the
same package that only work together. A record without the field still means the normal
single-executable package, so nothing that worked before changes.

Installing a tree package with a client that predates this release is not "slightly off" —
it is broken, because the old client keeps only `bin/<name>` and the rest of the tree is
gone. Records can therefore declare a floor:

```
min_client_version: "4.5.2"
```

An older client refuses such a record instead of installing half of it; `-F` / `--force`
still installs it anyway, with a warning. A record without the field installs as before.

## 2. Install and uninstall take lists

```
$ wave install jq, yq, ffmpeg@6.1
$ wave uninstall ffmpeg@6.1@6.0, jq@all
$ wave uninstall jq -a
```

- Commas separate packages; a space works too — `wave install jq yq` installs both. Before
  this release the extra words were dropped silently, which looked like "installed".
- Each entry may carry its own `@version`, and one package may name several versions.
- `@all` (the older `@*` still works) means every installed version; `-a` / `--all` is the
  flag form of the same thing. Combining `-a` with an explicit version is refused rather
  than guessed.
- Each entry is installed or removed on its own: one bad name does not stop the rest. The
  summary at the end reads `Installed 2 of 3 package(s)` and names what failed; the exit
  status is non-zero if anything failed.
- A full-width comma (`，`, `、`, `﹐`, `､`) is rejected before the package names are parsed,
  and the corrected line is printed — passing it through only produced "package jq，yq is
  not installed", which looks like the index is at fault.

## 3. `wave basedir`

The install root was only visible by opening `config.json`. It is now a command:

```
$ wave basedir
🌊 ~/.local/linuxwave
$ wave basedir --raw
/home/you/.local/linuxwave
```

`--raw` drops the emoji and folds nothing, so it can be used in scripts. Setting the
directory (`--set`) is 4.6 work and is not in this release.

## 4. An interrupted tree install no longer wedges the package

Tree packages keep their whole directory under `bin/<name>@<version>/`, and the installer
used to move the fresh tree into a target that `mkdir -p` had already created. If a previous
attempt had been interrupted, that target still held a partial tree, and `mv` refuses to
merge into a non-empty directory of the same name:

```
$ wave install git
mv: rename …/share to …/bin/git@2.56.1/share: Directory not empty
```

Retrying was pointless — the leftover was exactly what made the next attempt fail — and the
only way out was to `rm -rf` the path by hand. The installer now removes the old target
before moving anything in, and the "is this path inside the install tree?" check runs
unconditionally instead of only when the target already existed.

## 5. `downloads/tmp` cleans up after itself

A `.partial` file has two normal endings: renamed when the download completes, or deleted
when the command fails. An interrupted one (Ctrl-C, dropped connection, closed lid) is what
`-C` resumes from — but once you stop retrying, it sits in `downloads/tmp` holding anywhere
from a few hundred MB to several GB, and that directory appears in neither `wave list` nor
any uninstall path.

`install` and `uninstall` now remove `.partial` files whose mtime is more than **7 days**
old, and say so:

```
🌊 Cleaned up 2 stale partial download(s) from ~/.local/linuxwave/downloads/tmp (untouched for 7+ days): a.partial, b.partial
```

It is best-effort — a file that cannot be removed is skipped, never failing the command —
and it does not ask first. Nothing older than the threshold is kept, nothing younger is
touched, other files in the directory are left alone, and `-s` stays quiet.

## 6. Known limitations

- **No `min_os` equivalent.** Linux has no Mach-O `minos` field, and LinuxWave does not
  substitute a glibc requirement — a package needing a newer glibc fails at run time.
- **There is still no install-tree mutex.** MacWave 4.6 takes a lock so two `wave` runs
  cannot rewrite `bin/` and `links/` at the same time. This release does not; the
  `downloads/tmp` sweep above is best-effort for the same reason.
- bash 4.4 or newer is required for the installer and the self-update script.
- Signature verification is enforced only with `LINUXWAVE_STRICT_HASHES=1`.

## 7. Assets

Every `.py` / `.sh` file at this tag (flattened), the two source-tree archives,
`SHA256SUMS` and `SHA256SUMS.asc`.

| Asset | What it is |
| --- | --- |
| `*.py`, `*.sh` | every source file at this tag, without directories |
| `linuxwave-4.5.2-archive.tar`, `.tar.gz` | the whole tree, top-level directory `linuxwave-4.5.2/` |
| `SHA256SUMS` | SHA-256 of every asset above |
| `SHA256SUMS.asc` | detached GPG signature over `SHA256SUMS` |

# LinuxWave 4.5.2

**LinuxWave 4.5.2** · 构建号：**328B1254** · 发布于 **2026-11-24** · 发布分支：`4.5`

这一版把 LinuxWave 追到 MacWave 4.5.2（这些文件就是从那条线移植过来的）。带来三件事：
一个软件包可以是整棵目录而不只是一个可执行文件；`install` 与 `uninstall` 可以一次收多个
条目；整树包装到一半被打断之后，这个包不会再永远装不上。此外还有 `wave basedir`，以及
一件 LinuxWave 先有、MacWave 要到 4.6 才有的东西：`downloads/tmp` 会自己打扫。

## 升级方式

`wave selfupdate` 就够。`4.4` 与 `4.5` 的主版本号都是 `4`，不算跨大版本，不需要重装：

```bash
wave selfupdate
```

## 1. 一个包现在可以是一棵树

有些工具不是一个文件。`git` 需要 `libexec/git-core/git-remote-https` 与
`share/git-core/templates`，neovim、helix 需要 `runtime/`。版本记录现在可以写：

```
install: "tree"
```

安装器会把整棵解压目录留在 `bin/<名称>@<版本>/` 下，写一个 `.is_a_tree` 标记，并把
**`bin/` 下的每个可执行文件**都链出去 —— 不只主命令，因为 `git-upload-pack`、`dtc` 的
`fdtget`、`testdisk` 的 `photorec` 都是同一个包里必须一起用的命令。没有这个字段的记录
仍然是原来的单文件包，以前能装的照旧。

用这一版之前的客户端装整树包不是「略有偏差」，而是**一定装坏**：旧客户端只留
`bin/<名称>`，树的其余部分全丢。所以记录可以声明下限：

```
min_client_version: "4.5.2"
```

更旧的客户端会拒绝这条记录，而不是装一半；`-F` / `--force` 仍然可以硬装，只是会警告。
没有这个字段的记录按原样安装。

## 2. install 与 uninstall 收列表

```
$ wave install jq, yq, ffmpeg@6.1
$ wave uninstall ffmpeg@6.1@6.0, jq@all
$ wave uninstall jq -a
```

- 逗号分隔多个包；空格也认 —— `wave install jq yq` 装两个。这一版之前多出来的词会被
  **静默丢掉**，看起来像「装上了」。
- 每个条目可以带自己的 `@版本`，同一个包也可以连写多个版本。
- `@all`（旧写法 `@*` 继续认）表示这个包的全部版本；`-a` / `--all` 是同一件事的旗标
  写法。`-a` 与显式版本混用会直接拒绝，不猜谁说了算。
- 每个条目各自安装或卸载：一个名字打错不影响其余。末尾汇总 `Installed 2 of 3
  package(s)` 并点名失败的；有失败就以非 0 退出。
- 全角逗号（`，`、`、`、`﹐`、`､`）在解析包名之前就被拦下，并把改好的那行打出来 ——
  放过去只会得到「找不到包 jq，yq」这种看不出毛病的报错。

## 3. `wave basedir`

安装根目录以前只能打开 `config.json` 才看得到，现在有命令：

```
$ wave basedir
🌊 ~/.local/linuxwave
$ wave basedir --raw
/home/you/.local/linuxwave
```

`--raw` 不带 emoji、也不折成 `~`，可以直接进脚本。改目录（`--set`）属于 4.6 的内容，
这一版没有。

## 4. 整树包装到一半被打断，不会再卡死

整树包把整棵目录放在 `bin/<名称>@<版本>/` 下，而安装器以前是把新树 `mv` 进一个已经由
`mkdir -p` 建好的目标目录。如果上一次安装被打断，那个目标里还留着半棵树，而 `mv` 拒绝
往非空的同名目录里合并：

```
$ wave install git
mv: rename …/share to …/bin/git@2.56.1/share: Directory not empty
```

重试没有意义 —— 正是那半棵树让下一次尝试失败 —— 唯一的出路是手工 `rm -rf` 那个路径。
现在安装器会在往里搬之前先删掉旧目标，而且「这个路径是否在安装树内」的检查改成无条件
执行，不再只在目标已存在时才跑。

## 5. `downloads/tmp` 会自己打扫

`.partial` 只有两个正常归宿：下载完成后改名，或者这次命令失败时被删掉。被打断的那一份
（Ctrl-C、断连、合盖）是 `-C` 续传用的 —— 可一旦用户不再重试，它就待在 `downloads/tmp`
里占着几百 MB 到几 GB，而那个目录既不在 `wave list` 里、也不在任何卸载路径上。

`install` 与 `uninstall` 现在会清掉 mtime 超过 **7 天**的 `.partial`，并说一句：

```
🌊 Cleaned up 2 stale partial download(s) from ~/.local/linuxwave/downloads/tmp (untouched for 7+ days): a.partial, b.partial
```

尽力而为 —— 删不掉的就跳过，绝不让命令失败；也不事先询问。没超过门槛的一个不动、
非 `.partial` 的文件不动、`-s` 时不打印。

## 6. 已知限制

- **没有 `min_os` 的等价物。** Linux 没有 Mach-O 的 `minos` 字段，LinuxWave 也没有用
  glibc 版本要求去替代 —— 需要更新 glibc 的包会在**运行时**失败。
- **仍然没有安装树互斥锁。** MacWave 4.6 会加锁，让两个 `wave` 不会同时改写 `bin/` 与
  `links/`；这一版没有，上面那次 `downloads/tmp` 清理因此也是尽力而为。
- 安装器与自更新脚本要求 **bash 4.4 或更高**。
- 验签只在 `LINUXWAVE_STRICT_HASHES=1` 时硬失败。
